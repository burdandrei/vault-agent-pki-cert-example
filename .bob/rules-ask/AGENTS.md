# Project Documentation Rules (Non-Obvious Only)

- `certs/` contains only a `place_for_certs` placeholder — all `.pem` files are runtime-generated by Vault Agent and are gitignored.
- `datapower/certs/` similarly only contains a `place_for_certs` placeholder; actual cert files are volume-mounted into the container as `cert:///`.
- `datapower/config/auto-startup.cfg` is the source of truth for DataPower's crypto object layout: the TLS service (`ssl-test-fsh`) listens on port 8043, idcred `ssl-keystore` binds key `demo` + cert `demo`, and `rest-mgmt` is on 5554 without a custom SSL profile.
- `datapower.hcl` at the repo root uses `templates/dp-demo-1m.vtmpl` (1-minute TTL, for rapid testing), not `templates/dp-demo.vtmpl` (1-hour TTL, used in the init phase). The README describes the flow but does not note this TTL difference.
- The README's DataPower directory tree lists `webgui.vtmpl`, `dp-ui.vtmpl`, and `demo.vtmpl` but the actual filenames in `templates/` are `dp-webgui.vtmpl`, `dp-ui.vtmpl`, and `dp-demo.vtmpl`.
- nginx config resolves cert paths **relative to its config file location** (`../certs/`), so `nginx -c <absolute path>` is required — relative invocation breaks cert resolution.
